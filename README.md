# Wilkipedia

Every class at Wilcox High School, explained by students. A static website on
GitHub Pages with a Supabase database for accounts, bounties, submissions and
comments.

Read `docs/Wilkipedia Team Handbook.docx` first. It covers *what* we're
building and the rules. This file covers *how* it works.

---

## Run it on your computer

```bash
cd ~/Wilkipedia
python3 tools/build.py          # rebuild pages after changing anything in data/
python3 -m http.server 8765     # then open http://127.0.0.1:8765
```

It has to be served over http://. Double-clicking `index.html` won't work,
because the pages load data with `fetch()`.

## Demo mode vs live mode

Until `assets/js/config.js` has the Supabase URL and key, the site runs in
**demo mode**. Everything works, but claims, submissions and comments are saved
only in your own browser. Signing in just asks for a name and makes you an
admin, so you can try the whole loop yourself: claim → submit → review →
publish. On the Account page you can switch roles to see what a contributor sees.

## How content works

| What | Where it lives | Who changes it |
|---|---|---|
| Course list, grades, prerequisites, catalog descriptions | `data/catalog.json` (from the SCUSD 2025–26 catalog) | You, once a year: see `tools/parse_catalog.py` |
| Which teacher teaches what | `data/directory-raw.json` (from the Wilcox staff directory) + `data/course-aliases.json` | You, when teachers change |
| Starting bounties | `data/seed-bounties.json` | You. After launch, post bounties on the Review page |
| Everything students write | Supabase `submissions` table | Students submit, reviewers approve |

After changing anything in `data/`, run `python3 tools/build.py` and commit
the regenerated pages. GitHub Pages has no build step, so the HTML is committed.

A class shows as **green** once it has at least one approved submission, and
**grey** ("not written yet") until then.

## Setting up Supabase (one time, ~20 minutes)

1. **Create the project.** You've done this if you followed the chat steps:
   supabase.com → New project `wilkipedia`, region West US.
2. **Create the tables.** Supabase → **SQL Editor** → New query → paste all of
   `supabase/schema.sql` → **Run**. Then do the same with `supabase/seed.sql`
   (the starting bounties).
3. **Connect the site.** Supabase → **Project Settings → API Keys**. Copy the
   Project URL and the **publishable (anon)** key into `assets/js/config.js`.
   ⚠️ Never put the `service_role`/secret key or the database password in any file.
4. **Turn on Google sign-in:**
   1. Go to console.cloud.google.com → create a project called `Wilkipedia`.
   2. **APIs & Services → OAuth consent screen**: choose *External*, app name
      Wilkipedia, your email. Publish it.
   3. **Credentials → Create credentials → OAuth client ID**: type *Web application*.
      Under *Authorized redirect URIs* add `https://<your-project>.supabase.co/auth/v1/callback`
      (Supabase shows this exact URL on its Google provider page).
   4. Copy the Client ID and Client secret into Supabase → **Authentication →
      Sign In / Providers → Google**, then enable it.
   5. Supabase → **Authentication → URL Configuration**: set *Site URL* to the
      live site, and add these redirect URLs: `http://127.0.0.1:8765/**` and
      `https://<github-username>.github.io/**` (later, also your domain).
5. **Make yourself admin.** Sign in on the site once. Then Supabase → **Table
   Editor → profiles** → your row → set `role` to `admin`. Do the same for
   Jonathan with `reviewer` (or `admin`).

Roles: `contributor` (default) → `trusted` (automatic after 3 approved
submissions, so comments post instantly) → `reviewer` → `admin`. Only change
roles in the table editor.

## Putting it online (GitHub Pages)

1. Create a new repository on github.com called `wilkipedia`. Keep it empty: no README.
2. Push this folder:
   ```bash
   git remote add origin https://github.com/<your-username>/wilkipedia.git
   git add -A && git commit -m "Wilkipedia" && git push -u origin main
   ```
3. On github.com: repo → **Settings → Pages** → *Deploy from a branch* → `main` / `(root)`.
4. After a minute the site is at `https://<your-username>.github.io/wilkipedia/`.

**Live now at https://wilcoxwiki.org** (domain bought on Porkbun, with auto-renew on). DNS has four A records
(185.199.108–111.153) and `www` → `ethanahte.github.io`. The `CNAME` file in the repo root holds the domain; don't delete it.

**When you buy a domain:** add it in Settings → Pages → Custom domain, set
`SITE_URL` in `tools/build.py`, rebuild (that turns on `sitemap.xml` and
`robots.txt`), add the domain to Supabase's redirect URLs, then submit the
sitemap in Google Search Console.

```
  style.css            all styling (light + dark)

  js/ui.js             shared helpers: header, escaping, toasts, form renderer
  js/course.js         course page
  js/bounties.js       bounty board
  js/submit.js         contribute form
  js/review.js         reviewer desk
  js/pages.js          home, subjects, search, leaderboard, summer, school, account
data/                  the inputs listed above + generated courses.json and search.json
supabase/schema.sql    tables + security rules (row-level security)
supabase/seed.sql      GENERATED starting bounties
tools/build.py         the site generator (Python standard library only)
tools/parse_catalog.py rebuilds data/catalog.json from next year's catalog PDF
docs/                  the team handbook
```

## Security, briefly

The browser only ever has the public key. Everything that matters is enforced
in `supabase/schema.sql` with row-level security:
- anyone can read approved content
- only signed-in users can submit, comment, claim or report
- submissions start as `pending`; only reviewers can change status
- new members' comments start `held`
- a comment reported as inappropriate is hidden automatically until a reviewer looks at it
- users can change their display name but not their role

Everything students type is escaped before it is shown (`esc()` / `prose()` in `ui.js`).
